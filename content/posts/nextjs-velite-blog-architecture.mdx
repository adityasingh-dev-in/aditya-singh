# Building a Zero-Cost Blog with Next.js 15 and Velite

After spending years writing posts on platforms I don't control, I decided to build my own. The requirements were simple but exacting:

- **Git-backed content** — every post is a commit, every edit is reversible
- **₹0/month** — hosting, storage, search, comments: all free
- **Production-grade** — not a toy, a system I'd stake reputation on
- **In-browser CMS** — write from any device, not just VS Code

<Callout type="tip" title="TL;DR">
The entire system is statically generated by Next.js 15, content is parsed at build time by Velite, images live in Cloudinary, and publishing from the browser writes directly to GitHub via the Git Data API.
</Callout>

## Why Not a Headless CMS?

Contentful, Sanity, Strapi — they're excellent. But they introduce a paid tier ceiling the moment you want webhooks, scheduled publishing, or more than N API calls per month. More importantly, your content lives in someone else's database.

With Git as the database:

- Every post is a text file in a repo I own
- Full version history for free
- `git revert` is an undo button for bad posts
- No vendor lock-in

## The Content Pipeline

Velite is the modern, maintained replacement for Contentlayer. It's Zod-based, which means your post schema is type-safe by construction:

```ts
schema: s.object({
  title: s.string().max(120),
  slug: s.slug('posts'),
  date: s.isodate().or(s.string().regex(/^\d{4}-\d{2}-\d{2}$/)),
  description: s.string().max(250),
  tags: s.array(s.string()).default([]),
  published: s.boolean().default(true),
  body: s.mdx(),
})
```

At build time, Velite reads every `.mdx` file in `content/posts/`, validates the frontmatter against this schema, processes the MDX through rehype-pretty-code, and emits typed TypeScript from `.velite/`. No runtime parsing, no surprises.

## The Asset Dilemma

Binary assets (screenshots, diagrams, hero images) committed to Git cause slow clones and balloon repo size past the GitHub recommended 1 GB limit at around 100 posts.

The fix: **Cloudinary**. Generous free tier, global CDN delivery, and automatic WebP/AVIF format optimization. Images uploaded from the admin UI stream directly to Cloudinary using signed parameters — they never pass through Vercel's 4.5 MB serverless payload limit:

```ts
// 1. Get signed upload credentials from server
const { uploadUrl, signature, timestamp, apiKey, folder } = await getUploadCredentials()

// 2. Browser uploads directly to Cloudinary — zero Vercel involvement
const formData = new FormData()
formData.append('file', file)
formData.append('signature', signature)
formData.append('timestamp', String(timestamp))
formData.append('api_key', apiKey)
formData.append('folder', folder)
await fetch(uploadUrl, { method: 'POST', body: formData })
```
